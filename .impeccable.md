## Design Context

### Users

OpenKara is for casual singers using a desktop app to turn their own music files into karaoke tracks. Most users are not technical and should not need to understand audio-processing terms, storage details, or file-system jargon to complete setup, import songs, or start singing.

Primary jobs to be done:

- Set up a karaoke library without confusion
- Import songs they already own
- Start playback and sing along quickly
- Recover from errors without feeling blocked or blamed

The interface should assume users may feel uncertain during setup, impatient while waiting, and stressed when something fails.

### Brand Personality

The product voice should feel clean, minimal, and clear. Copy should be calm and low-friction rather than playful or technical. The emotional goal is steady confidence: users should feel guided, reassured, and in control.

### Aesthetic Direction

The app should feel like a focused desktop music tool: native, quiet, and intentional. Prioritize clarity over decoration and make audio-specific features feel approachable for non-experts. Avoid overly technical language, corporate phrasing, and hype-heavy copy.

### Design Principles

1. Use everyday language before technical terminology.
2. State what happened and what the user can do next.
3. Keep copy brief, but not so brief that it becomes vague.
4. Match the user's emotional state with calm, direct wording.
5. Use the same term consistently throughout the product.
